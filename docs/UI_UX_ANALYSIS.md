# MAZEWARD UI/UX分析 — 現状と改善提案

**作成日**: 2026-09-01  
**対象**: Minestomサーバー上で動作するタワーディフェンスゲーム  
**比較対象**: バニラMinecraft（Java Edition）のUI/UXベストプラクティス

---

## 1. MAZEWARD 現在のUI/UX（実装済み）

### 1.1 コア表示要素（HUD）

| 要素 | 実装内容 | 特徴 |
|---|---|---|
| **敵経路表示（青）** | パーティクルと敵移動ビジュアル | 敵がどの道を歩くか直感的に理解可能 |
| **障害物プレビュー（黄）** | 置こうとしているブロック形状を半透明表示 | 配置前の確認が可能 |
| **経路変化表示（赤）** | 障害物を置くと敵経路が変わる区間を強調 | 置く前に結果を予測できる（素晴らしい） |
| **敵残数ボスバー** | 波中の敵残数と進行率 | 波の進捗状況が一目瞭然 |
| **チャット表示** | コマンド実行結果とゲーム情報 | 操作結果がテキストで確認可能 |

### 1.2 操作体系

| 操作 | 手段 | 概要 |
|---|---|---|
| **モード切り替え** | ホットバー スロット9 クリック | ブロック ↔ タワーの即座切り替え |
| **形状選択** | 数字キー 1-8 | 素早く形状を選択 |
| **配置プレビュー** | 右クリック @ブロック位置 | 置く前に見た目と敵経路を確認 |
| **回転** | マウスホイール（UP/DOWN） または Q キー | 90度ずつ回転（4方向） |
| **配置確定** | 左クリック | 確定して手札消費 |
| **ウェーブ開始** | ホットバー スロット9 右クリック または !start | 戦闘開始 |
| **速度変更（観戦）** | ホットバー 1/2/3/4 スロット | 観戦モード限定で倍速変更可能 |

### 1.3 優れた点

1. **色による直感的な理解** ✓
   - 青＝敵経路、黄＝配置予定、赤＝変化区間の三色で直感的に意図が伝わる
   - バニラMinecraftでは使われていないゲーム固有の優秀な工夫

2. **配置前フィードバック** ✓
   - 敵経路の実時間変化表示
   - 「置くとどうなるか」を配置前に確認できるのは優秀
   - バニラでは「置いた後に壊す」という無駄が発生しやすいが、ここでは事前確認で解決

3. **モード切り替えの効率性** ✓
   - ホットバー スロット9 ワンクリックで即座に切り替え
   - ブロックモード/タワーモードの視覚的な違いが明確

4. **チャット操作とコマンド** ✓
   - !help, !state, !start などゲーム初心者向けの文字化されたコマンドが充実
   - バニラMinecraftのチュートリアル philosophy と一致

## 2. 発見した課題と改善提案

### 課題 A: ホットバー操作の複雑さ

#### 現状
- ホットバースロット9が**複数の役割を兼務**している
  - 単クリック → ブロック/タワーモード切り替え
  - 右クリック → ウェーブ開始（戦闘フェーズ）
  - 同じスロットに異なる役割が混在

#### バニラMinecraftとの比較
- バニラでは、各スロット(1-9)は**それぞれアイテムスタック専任**
- 操作と結果が一対一で対応しているため混乱が少ない
- スロット切り替え時に「選択したアイテム名」が画面上部に表示される

#### 改善提案
```
【案A】 スロット9を「モード切り替え専用」に統一
  - ウェーブ開始は別キー（例：Space、E キー、または!startコマンド）
  - スロット構成の明確化

  ホットバー：
  スロット 1-4: ブロック形状 × 4
  スロット 5-8: 次の選択肢（または予備）
  スロット 9: MODE TOGGLE （専用表示）

【案B】 ホットバー外にモード切り替えボタンを配置
  - 画面右下など常時見える場所にUI要素
  - ホットバースロット9をその他用途に解放
  - 操作体系をより直感的に
```

**影響度**: 中程度 | **実装難度**: 低（スロット機能の再割り当て）

---

### 課題 B: 敵経路プレビューの詳細さ不足

#### 現状
- 配置時に「敵がここを通る」という大まかな経路は見える
- しかし「敵の速度」「所要時間」「タワーの射程に入るか」などは表示されない

#### バニラMinecraftとの比較
- Minecraft のカスタムマップ（例：Redstone Device）では「回路の動作流」を色で見せている
- チュートリアルではゲームの重要なメカニクスを**ビジュアル化**して教えている

#### 改善提案
```
【案1】 敵経路上に「敵が到着する時間」を表示
  - パーティクル色を段階的に変える（例：赤→黄→緑）
  - または敵経路上の「タイミングマーク」を設置
  - プレイヤーが「この場所にタワーを置くと敵が何秒で通過するか」を予測可能に

【案2】 タワー射程表示を常時有効化
  - 現在：タワー配置時のみ射程を黄色パーティクルで表示
  - 改善：タワー選択時にも射程を表示し、配置前から効果範囲を確認可能に

【案3】 敵パラメータをHUDに表示
  - 敵残数ボスバーの横に「敵タイプ一覧」を表示
  - 例：[NORMAL x5] [FAST x2] [ARMORED x1]
  - プレイヤーが敵構成を事前に把握可能に
```

**影響度**: 低～中程度 | **実装難度**: 中（パーティクル管理とHUD拡張）

---

### 課題 C: チャットコマンドの可視性の低さ

#### 現状
- チャットコマンド (!help, !state, !start など) は強力だが、
  - **初心者は存在を知らない可能性が高い**
  - ホットバーには明示されていない
  - ゲーム内ドキュメントが無い

#### バニラMinecraftとの比較
- **ゲーム内チュートリアル**が充実している
  - 最初にスポーンした時にメッセージで操作を教える
  - F1 キーでHUD非表示にしたり、オプションで設定可能

#### 改善提案
```
【案1】 起動時のオンボーディングUI
  - ロビーに入った時点で「操作ガイド」を表示
  - 「ウェーブを開始するには？」など選択式ガイド
  - ゲーム初回プレイ時のみ表示

【案2】 チャットにコマンド候補を表示
  - "!" と入力した時点で利用可能なコマンド一覧をサジェスト
  - タブ補完機能 (minecraft-cli style)

【案3】 ホットバーアイテム名にコマンド情報を記載
  - 例：「[MODE] Ctrl+9で切り替え」
  - アイテム選択時に表示される名前にヒントを含める

【案4】 画面内にボタンUIを配置
  - 画面右下にボタン "WAVE START"、"SHOW HELP" など配置
  - マウスで視認可能なUI要素として配置
```

**影響度**: 中程度 | **実装難度**: 低～中（新UIレイアウト追加）

### 課題 D: ブロック・タワーの「残在庫」表示不足

#### 現状
- ホットバーのアイテムスタック数（右下の数字）は表示されている
- しかし**タワーは「無制限」なので数字が出ない**
  - 初心者は「タワーをいくつ置いてもいい」ことを理解しにくい

#### バニラMinecraftとの比較
- バニラでは、各アイテムのスタック数が明確に表示される
- 「64個まで持てる」「無制限」などが一目瞭然

#### 改善提案
```
【案1】 タワーアイテム名に「無限」アイコンを付与
  - 例：「Basic Tower ∞」「Cannon ∞」
  - スタック表示位置に ∞ マークを表示
  - ブロックとの違いを視覚的に強調

【案2】 タワーアイテムに異なるアイテムタイプを使用
  - ブロック：dirt, cobblestone など（消費型）
  - タワー：特別なアイテム（例：display entity）で表現
  - ホットバー表示を根本的に変える

【案3】 ゴールド消費を画面に表示
  - タワー配置時に「Cost: 15G」をアイテム上部に表示
  - 「置くたびにゴールドを消費する」ことを明示
```

**影響度**: 低程度 | **実装難度**: 低（表示テキストの追加）

---

### 課題 E: 敵経路変更（戦闘中の配置）の体験が不明確

#### 現状
- 戦闘中にブロックを置くと敵経路が動的に更新される（優秀）
- しかし**「経路の引き直し」が明示的に表示されない**
  - 古い経路のパーティクルがまだ表示されたまま？
  - 新しい経路への切り替わりが目立たない可能性

#### バニラMinecraftとの比較
- Minecraft では信号更新時に**リアルタイムで物理演算が反映**される
- プレイヤーは「あ、変わった」という実感がある

#### 改善提案
```
【案1】 経路更新時の「フラッシュ効果」
  - 新しい敵経路の出現時に、パーティクルを白や明るい色でフラッシュ
  - 視覚的に「今、経路が変わった」と認識させる

【案2】 古い経路と新しい経路を異なる色で表示
  - 古い経路（薄い青 or グレー）
  - 新しい経路（鮮やかな青）
  - 切り替わりが一目瞭然

【案3】 敵の「ショック」表現
  - 敵ユニットが新経路に切り替わるとき、ブザー音やパーティクルを演出
  - ゲーム的な緊張感を高める
```

**影響度**: 低程度（ゲーム性には影響なし） | **実装難度**: 低～中（VFX追加）

### 課題 F: タワー強化UIの発見性の低さ

#### 現状
- タワー右クリック → インベントリGUIが開く（実装済み）
- しかし**「右クリックしたら何が起こるか」初心者は知らない**

#### バニラMinecraftとの比較
- 各ブロックの右クリック動作は統一されている
- チェストなら「中身が見える」、ドアなら「開閉」など直感的

#### 改善提案
```
【案1】 タワー配置直後にUIヒント表示
  - 「このタワーを右クリックで強化できます」というチャットメッセージ
  - 最初の3つのタワー配置時のみ表示

【案2】 タワーの上に「強化可能」フラグを表示
  - タワーの頭上に小さなパーティクル（例：🔧アイコン的な表現）
  - 右クリック可能なことを視覚的に示唆

【案3】 UI要素を3D空間内に配置
  - タワーの脇に「Upgrade [RMB]」というテキスト表示
  - Minecraft カスタムマップ的な approach
```

**影響度**: 低程度 | **実装難度**: 低（チャットメッセージまたは簡単なVFX）

---

### 課題 G: スコアボード/統計画面の欠落

#### 現状
- ゲーム中の統計情報（ゴールド、HP、敵撃破数など）はスコアボードに表示
- しかし**ゲーム終了後のリプレイ統計が無い**

#### バニラMinecraftとの比較
- タイトル画面で「Stats」メニューがある
- Slay the Spire など同じジャンルのゲームは「ラン終了後の統計画面」が充実

#### 改善提案
```
【案1】 ゲーム終了後の「結果画面」
  - ゲーム終了（勝利/敗北）時に統計を表示
  - 撃破敵数、得金、敵経路の長さ、タワー数 等

【案2】 ロビーに「ランキング / 過去のゲーム結果」表示
  - 最高記録（7層クリア）までの進捗
  - 前回のゲームサマリー

【案3】 デッキビルダーの「おすすめ」機能
  - AIが学習データから「強いデッキ構成」をサジェスト
  - 「このブロック形状の組み合わせは相性が良い」という情報提供
```

**影響度**: 低～中程度 | **実装難度**: 中（新UIの設計と実装）

## 3. マインクラフト好事例から学ぶ設計原則

### 原則1: 「色と記号」の統一性

**Minecraft の手法:**
```
❤️ 赤 = 健康（ハート）
🍖 黄 = 空腹（肉/パン）
⭐ 緑 = 経験値
🛡️ 灰 = 盔甲
☁️ 白 = 吸収効果
```

**MAZEWARD への適用:**
```
✅ 現在：青（敵経路）、黄（配置予定）、赤（変化区間）→ 非常に優秀
⚠️ 今後：敵タイプごとに色を変えるか？
  例：通常敵 = 青、高速敵 = 黄、装甲敵 = オレンジ、ボス = 赤
```

### 原則2: 「1アクション = 1フィードバック」

**Minecraft の手法:**
- ブロック置く → ブロック配置＆音
- アイテム投げ捨て → 消える＆音
- 敵倒す → ドロップ＆音＆粒子

**MAZEWARD への適用:**
```
✅ 現在：配置時にチャットで通知 → 優秀
⚠️ 改善案：
  - 敵経路フラッシュ（視覚的フィードバック）
  - 配置成功音
  - タワー配置時のビジュアル演出
```

### 原則3: 「新規プレイヤーへの段階的な教育」

**Minecraft の手法:**
```
1. 起動時のチュートリアル
2. F3 キーで詳細情報表示（初心者向けじゃない）
3. Wiki への リンク
```

**MAZEWARD への適用:**
```
✅ 現在：!help コマンドがある
⚠️ 改善案：
  1. 最初のロビーで「操作ガイド」を表示
  2. 各フェーズで「次に何をすべきか」をチャットで教える
  3. デッキ選択画面に詳しい説明を付与
```

### 原則4: 「HUD の最小化」

**Minecraft の手法:**
- F1 で HUD 完全非表示可能
- 必要な情報だけを画面に置く
- 視認性とゲーム画面の調和

**MAZEWARD への適用:**
```
✅ 現在：敵経路の青パーティクルが視認性を損なっていないか？
⚠️ 確認項目：
  - 敵経路の透明度は適切か
  - パーティクル数が多すぎないか
  - スコアボードはどこに表示されるか
```

| **敵経路更新フラッシュ** | 戦闘中の変化が実感できる | 低 |

## 5. 結論

MAZEWARD の UI/UX は**ゲーム固有のメカニクス（色による経路表示）を活かした優秀な設計**である。
一方、以下の点で改善の余地がある：

### 強み ✓
- 敵経路を色で直感的に表示（バニラにない工夫）
- 配置前フィードバック（プレイヤーの試行錯誤を助ける）
- チャットコマンドによる柔軟な操作

### 弱み ⚠️
- 初心者向けの段階的教育が不足
- ホットバーの役割混在（操作の混乱につながる可能性）
- 戦闘中の動的更新が視覚的に目立たない

### 改善方向
1. **新規プレイヤー向けガイド強化** → チュートリアル・オンボーディング充実
2. **視覚フィードバック拡充** → パーティクル・音・HUD表示の充実
3. **操作体系の明確化** → ホットバーとコマンドの役割分離
4. **高度なプレイをサポート** → 敵パラメータ・タワー射程・時間情報の可視化

これらの改善により、**バニラMinecraft の思想（直感的・段階的・拡張可能）** を守りながら、
**MAZEWARD 独自の創造的な迷路構築体験** をさらに磨くことができる。
