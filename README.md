# MAZEWARD

Minecraft Java Edition 上で動く **迷路構築型ローグライト・タワーディフェンス**。

手札として配られた「形状カード」を配置して敵の経路を自分で設計し、
その障害物の上にタワーを建てて防衛する。Emberward の
「迷路構築 × タワーディフェンス」というコアコンセプトを参考にしつつ、
Minecraft の 3D 空間・ブロック・パーティクル・Display Entity を前提に設計し直したもの。

設計の全文（Emberward 調査、ゲームデザイン上の問題点と対策、ルール、アーキテクチャ）は
**[docs/MAZEWARD_DESIGN.md](docs/MAZEWARD_DESIGN.md)** にある。

## 遊び方

### 起動

```bash
./run.bat
```

`start-server.ps1` が JDK 25 とローカル Gradle を自動で探して起動する。
起動後、**無改造の Minecraft Java Edition 1.21.11** で `localhost` に接続するだけ。
クライアント MOD もリソースパックも不要。

Git Bash から直接動かす場合:

```bash
JAVA_HOME="/c/Program Files/Java/jdk-25" ./.tools/gradle/gradle-9.1.0/bin/gradle run
```

### 操作

| 操作 | 効果 |
|---|---|
| ホットバー **1〜5** | 障害物カードを選ぶ（手札） |
| ホットバー **6** | 選択中のタワー |
| ホットバー **7** | タワー一覧を開く |
| ホットバー **8** | 強化 / 売却（タワーを狙って右クリック） |
| ホットバー **9** | ウェーブ開始 |
| **左クリック** | 選択中の形状を 90° 回転 |
| **右クリック** | 確定（配置 / メニューを開く / ウェーブ開始） |
| チャット `!help` | 操作一覧 |
| チャット `!state` | 現在の状態 |
| チャット `!next` | 進行が止まったときの復帰 |

壁は 1 ブロック高。上空から俯瞰したときに迷路の形がいちばん読みやすい高さにしてある
（バニラなら 1 ブロックは乗り越えられるが、ここではゲームルールとして無視する）。

プレイヤーは常に飛行状態でアリーナ上空にいる。
視線と床の交点でセルを狙うので、Minecraft の到達距離に関係なく遠くのマスも指定できる。
アリーナは虚空に浮かぶ島なので、視認性のため常時暗視がかかっている
（画面端の渦巻きとステータスアイコンは経路表示の邪魔になるので消してある）。

### 画面の色（このゲームの中心となる UI）

| 色 | 意味 |
|---|---|
| 🔵 **青** | 現在の敵の経路（曲がり角は大きい粒で強調） |
| 🟡 **黄** | いま置こうとしている障害物 |
| 🔴 **赤** | その障害物を置くと **変わる区間だけ**（変わらないなら出ない） |
| 🟣 紫の直線 | 飛行敵が通る直線ルート（迷路を無視する） |
| ⬛ 赤いゴースト | そこには置けない（理由が頭上に出る） |

カーソルの上には **置けないときだけ** 理由が出る（「敵の経路が完全に塞がれます」など）。
形も角度もゴーストを見れば分かるので、文字は最小限にしてある。

赤は経路が変わる区間にしか出ないので、**赤が出たら経路が変わった** と一目で分かる。

敵は **角から角へ直線で** 移動する。角度は 45° 単位に縛られず、
曲がり角は障害物の角ではなく **障害物に接している通行可能ブロックの中心** になる。
そのぶん「壁で少し押しただけ」では敵が斜めに突っ切ってしまうので、
どこを塞げば本当に遠回りさせられるかを読む必要がある。

### ゲームの流れ

```
ロビー（星を右クリック）
   ↓
ロードマップ（浮島。第1層からボスまで全部見える。道をたどって足場に乗る）
   ↓
ステージ
   建築フェーズ ── カード配置（無料）／タワー購入（ゴールド）
        ↓ ウェーブ開始
   戦闘フェーズ ── 敵が経路を歩く／タワーが自動で撃つ
                   カード配置もタワー購入も継続してできる
        ↓ 全ウェーブ制圧
   報酬 3 択（タワー解放／カード／レリック／ゴールド）
   ↓
次の層 …… 第7層でボス
```

**障害物は戦闘中でも設置できる。** 敵が進軍している最中に壁を足して経路を変えれば、
すでに湧いている敵もその場から経路を引き直して進み直す。

ただし **一度置いた壁は撤去できない**（カードもその場で消費される）。
置いては壊してを繰り返して敵を往復させる「ジャグリング」は、
そもそも壊す手段がないので成立しない。

戦闘中の配置には 2 つだけ追加の条件がある。

- 敵が立っているセルには置けない
- 生きている敵を閉じ込めてしまう配置は弾かれる

## ゲームの中心にある 2 つの意思決定

1. **経路を伸ばすか、タワーの土台を作るか**
   カードは有限（ステージ内で消費される）。同じ 1 枚を
   「遠くに置いて敵の移動距離を伸ばす」ことにも
   「キルゾーンに 2x2 の土台を作る」ことにも使える。必ず奪い合う。

2. **経路の "長さ" ではなく "形"**
   雷塔は隣接する敵に連鎖するので、蛇行して経路が平行に並ぶほど強い。
   一方で飛行敵は迷路を完全に無視して直線で来るので、
   長さだけを追った構成は必ず崩れる。

3. **どのルートでボスまで行くか**
   ロードマップは 2 択の繰り返しではなく、1 層 3〜5 ノードが辺でつながったグラフ。
   1 ノードから道は 1〜2 本伸び、道どうしは交差する。
   全体が最初から見えているので、「ここで左に逸れると商店を 2 つ拾えるが精鋭を 1 回踏む」
   といった数手先を見た経路選択ができる。
   道はパーティクルの直線で描くので、交差していても目でルートを追える。
   通ってきた道は金色に残る。

4. **どのカードにルーンを刻むか**
   ルーンはカード 1 枚に付き、そのカードが作る壁すべてに乗る。
   「補強を刻んだ 2x2 は砲塔の土台にしたいから、経路を伸ばすのには使えない」
   というふうに、同じ 1 枚の奪い合いがもう一段深くなる。

## 実装方式

| 方式 | 判定 | 理由 |
|---|---|---|
| Vanilla Datapack | ✗ | リアルタイム A*・ゴーストの追従・手札 UI が現実的に不可能 |
| Fabric / NeoForge Mod | △ | 可能だがバニラ Mob AI とワールド生成を抱えたまま戦うことになる |
| **Minestom**（採用） | ◎ | Java 製のサーバ実装。**バニラクライアントがそのまま繋がる**。エンティティと経路を 100% 自前制御でき、Mob AI が邪魔しない |

- 対象バージョン: **Minecraft Java Edition 1.21.11**（Minestom `2026.03.25-1.21.11`）
- Display Entity（1.19.4+）を前提にしているので要求仕様の 1.16.5 は下限としては満たすが、
  ゴースト表示の質が落ちるため 1.21 系を推奨バージョンとして選定した。

## アーキテクチャ

`core` パッケージは **Minestom に一切依存しない純粋ロジック**。
マップ／経路探索／障害物／タワー／敵／ステージ進行を相互に依存させていないので、
どれか 1 つを差し替えても他が壊れない。

```
dev.antigravity.mazeward
├── MazewardMain / MazewardServer   起動とイベント配線
├── Mazeward                        全体コントローラ（ロビー / ロードマップ / ステージ遷移）
├── core/     Vec2i Rot Shape Shapes CellType Grid PathFinder PathResult
├── stage/    Phase StageConfig StageGenerator Waves Stage
├── tower/    Element AttackStyle TowerKind TowerInstance
├── enemy/    MoveMode EnemyKind EnemyInstance
├── run/      BlockCard Rune Deck Relic Roadmap RunState
├── world/    Palette ArenaRenderer Overlay
├── ui/       PlayerSession Hud Menus
└── dev/      SelfCheck CombatSim   （ヘッドレス検証）
```

### 拡張のしかた

| やりたいこと | 触る場所 |
|---|---|
| タワーを増やす | `TowerKind` に enum 定数を 1 つ足す |
| 敵を増やす | `EnemyKind` に enum 定数を 1 つ足す |
| 障害物の形状を増やす | `Shapes` に 1 行足す |
| レリックを増やす | `Relic` に 1 つ足し、`RunState` の補正メソッドを 1 つ足す |
| ノード種別を増やす | `Roadmap.NodeKind` に 1 つ足し、`Mazeward#enterNode` に分岐を 1 つ |
| ルーンを増やす | `Rune` に 1 つ足し、`Stage#resolvedStats` か `Stage#applyFieldRunes` に分岐を 1 つ |
| 見た目を変える | `Palette` |

### 「完全封鎖」ルールの差し替え

敵の経路を完全に塞ぐ配置は `Grid#checkPlacement` が
`Placement.WOULD_BLOCK` を返して弾く。判定はこの 1 箇所に閉じているので、
将来「封鎖はできるが敵が壁を殴って壊す」ルールにしたければここだけ変えればよい。

## 検証（Minecraft クライアント不要）

### 純粋ロジックの検査

```bash
./build.sh selfCheck
```

- 形状カタログの回転が全て正規化されているか
- **任意角度になっているか**（障害物なしで折れ点 0＝一直線、45°でない区間が出る、
  折れ点がすべて「障害物に接した通行可能セル」、斜めの壁を角抜けできない）
- **経路探索が決定論的か**（同じ盤面から必ず同じ経路。プレビューの信頼性の根拠）
- 完全封鎖の禁止（スポーン包囲の試行 + ランダム配置 4000 回で経路が絶対に残るか）
- ステージ生成 252 パターンが全て検証を通るか
- サンプル盤面を ASCII で出力

### 戦闘ループの通し実行

```bash
./build.sh combatSim --args="12"
```

疑似プレイヤー（経路が最も伸びる置き方を選び、経路と飛行ルートの近くにタワーを並べる）が
第 1 層からボスまで実際の `Stage` を回して、難易度カーブを出力する。
バランス調整はこの出力を見て行っている。

手札を 2 枚残して戦闘中にも増築するので、**戦闘中の配置と経路の引き直し** もここで走る。
毎 tick 「地上の敵が全員、通行可能なセルの上にいるか」を検証しているため、
引き直し漏れ（敵が壁をすり抜ける）があれば即座に失敗として出る。

## 現在の実装状況

**完了**

- 形状カード 13 種・回転・配置・手札／デッキ
- 任意角度経路探索 Theta*（角から角へ直線・角抜け禁止・決定論的）
- 現在経路（青）／配置予定（黄）／予測経路（赤）の同時表示
- 飛行敵の直線ルート表示
- タワー 6 種（形状・属性・攻撃方式・3 段階強化・売却）
- 塔ごとの発射音と、実際に飛ぶアイテム弾（矢・雪玉・ファイヤーチャージ…）
- 属性で色分けしたダメージ数字（背景の灰色板なし）
- 通貨 2 種（ステージ内のゴールド / ステージ間のエンバー）
- 敵 6 種（地上／飛行／装甲／回復／ボス）
- ウェーブ進行・勝敗判定・コア HP
- 戦闘中の障害物設置（生きている敵の経路をその場で引き直し）
- ローグライト 7 層（物理的な浮島のノードグラフ。全層と道が最初から見える）
- 1 枚のカード = 1 種類のブロック（地域テーマごとに 6 種類）
- 報酬 3 択・商店・祭壇・イベント・レリック 10 種
- ルーン 6 種（特殊障害物。カード 1 枚に付与して壁に効果を乗せる）
- ルールベースのステージ生成（生成 → 経路検証 → 再生成）

**今後**

- タレントツリーなどのメタ進行とセーブ
- 地形ギミック（溶岩タイル・回復トーテム）
- マルチプレイ協力
